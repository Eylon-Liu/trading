1. Architecture Strengths

Before enhancements, it is worth documenting what this system already does well. Several design decisions reflect genuine production quant experience and should be preserved in any refactor.

  • Point-in-time discipline is structural, not advisory. Every read function gates on filed date, never period_end. A backtest physically cannot see future filings. This is the single most important property of the system.
  • The system refuses to produce misleading backtests. DegradedBacktest exception, survivorship gap checks, and backtest_window() all refuse to run when data cannot support honest results. Most quant tools silently produce garbage for any date range.
  • Factor construction is academically sound. Proper MOM_12_1 (skipping last month), Wilder's RSI, yields instead of raw EPS, MAD winsorization with fallback, sector z-scores with minimum-member guards.
  • XBRL data quality is actively defended. Share-count cross-checking (reported vs. EPS-implied), split adjustment for filed counts, proxy statement filtering, tag selection heuristics, CIK lineage for successor-issuer reorganizations.
  • Redundancy is managed through documented correlation analysis. Strategy comments record pairwise correlations and justify factor removals (EBIT_TO_EV at 0.80 with EARNINGS_YIELD, MOM_6_1 at 0.88 with RETURN_6M).
  • Performance is optimized where it matters. Parallel factor computation, pre-loaded bulk data for backtests, incremental fundamental rebuilds, vectorized operations, disk-based factor cache with data-version fingerprinting.
  • Error isolation in the data pipeline. A failed source never aborts the sync. Fill-never-override for external data. Atomic cache writes.

2. Bugs & Correctness Issues

These should be fixed before any enhancement work. They affect the accuracy of current results.

P0 Sharpe ratio omits risk-free rate

quant/backtest.py — sharpe = cagr / vol overstates Sharpe in high-rate environments. With 3-month T-bills at 5%, a strategy returning 12% with 15% vol reports Sharpe 0.80 instead of the correct 0.47. Fix: subtract RISK_FREE rate (already configured as DGS3MO in config) from CAGR before dividing by vol.

P0 Trade backtest double-counts capital on overlapping positions

quant/backtest.py:579 — Monthly scans can open positions in the same name from consecutive months. P&L is summed by exit date without tracking capital allocation. The equity curve may overstate returns when positions overlap. Fix: track active capital per position and reject entries that would exceed portfolio capacity.

P0 Redundant correlated factors in insider_cluster strategy

quant/strategies.py:295 — INSIDER_NET_BUY and INSIDER_CLUSTER correlate at 0.98 per the long-term strategy's own comment, but both are kept in the mid-term insider_cluster strategy. This effectively double-weights insider activity. Fix: drop INSIDER_CLUSTER and redistribute its weight.

P1 pd.io.json.dumps() removed in modern pandas

data/news.py:142 — The pd.io.json.dumps function was deprecated and removed. The str() fallback produces non-JSON output that cannot be reliably deserialized. Fix: use json.dumps() from the standard library.

P1 datetime.utcnow() deprecated in Python 3.12+

data/sync.py (multiple locations) — Used throughout the sync orchestrator. Replace with datetime.now(timezone.utc) to suppress deprecation warnings and prepare for future removal.

P1 Finnhub rate limiting not actually enforced

data/marketdata.py — BATCH_PAUSE_EVERY = 55 is defined but never referenced. No actual pause logic exists. If Finnhub throttles, errors are silently swallowed. Fix: implement the batch pause or use the existing core.http rate limiter.

P1 Attention data re-fetches entire 2-year history on every sync

data/altdata.py — No incremental fetch logic. With 500 tickers, every refresh cycle makes 500 API calls each returning 730 data points. Fix: query existing max date per ticker and fetch only the gap.

P2 Signal generation uses Python for-loop over all rows

quant/engine.py:305 — [fn(row) for _i, row in merged.iterrows()] is a performance bottleneck for large universes. Fix: vectorize using np.select() with condition arrays.

P2 SIC 5912 misclassified

data/classify.py — "Drug Stores and Proprietary Stores" maps to Health Care, but CVS and Walgreens self-classify as Consumer Staples in GICS. Minor impact since few S&P 500 names hit this code.

3. Strategy Enhancements

3.1 Market-Neutral & Long-Short Construction

High Impact Add long-short portfolio construction

The system is long-only. The quality_breakdown inverted strategy surfaces names to avoid but does not model shorts. Add dollar-neutral portfolio construction: long top quintile, short bottom quintile, with configurable gross/net exposure. This is the standard way to test whether a factor actually predicts returns vs. merely correlating with the market.

High Impact Sector exposure constraints

Position sizing is purely risk-based with no sector concentration check. A value strategy can easily put 40% into Financials. Add configurable sector weight caps (e.g., max 25% per sector) and sector-relative position sizing. The neutralize() function in transforms.py already implements OLS regression neutralization — extend this to portfolio-level constraints.

Medium Impact Multi-factor combination research

Factor weights are set by conviction, not optimized. Add an IC-weighted combination option: weight each factor by its trailing information coefficient. This is less overfitting-prone than full mean-variance optimization and provides an empirical baseline to compare against the conviction-based weights.

3.2 New Strategy Families

Medium Impact Macro regime overlay

Strategies run identically in all environments. Add a regime detection layer using yield curve slope (2Y-10Y spread), VIX level, credit spreads, and leading economic indicators. In risk-off regimes, automatically shift toward quality/low-vol factors and reduce position sizes. The macro table already exists in the schema but has no data pipeline.

Medium Impact Event-driven strategies

The 8-K event data and insider transaction pipeline are mature but underutilized. Build dedicated event-driven strategies: post-earnings announcement drift (PEAD) with SUE scores, insider cluster buying with a 30-day holding window, and spin-off / restructuring plays using the corporate_events table. The earnings_drift mid-term strategy is a start but lacks standardized unexpected earnings (SUE).

Medium Impact Statistical arbitrage pairs

Add cointegration-based pair trading within sectors. The factor infrastructure (sector z-scores, correlation matrices) provides the foundation. Screen for pairs with high correlation, test for cointegration (Engle-Granger or Johansen), and generate mean-reversion signals when the spread exceeds 2 standard deviations.

4. Risk Management

4.1 Portfolio-Level Risk

Critical Liquidity filter

No minimum volume or ADV filter is applied during scoring. Small illiquid names can appear in the ranking and be untradeable at the suggested weight. config.py defines MIN_DOLLAR_ADV=1M but it's only used in universe presets, not enforced in the scoring engine. Add a hard gate: reject any name where the suggested dollar position exceeds 1% of 20-day average daily volume.

High Impact Portfolio-level VaR and stress testing

No portfolio-level risk metrics exist. Add: (1) historical VaR at 95% and 99% confidence, (2) parametric VaR using the covariance matrix, (3) conditional VaR (expected shortfall), (4) stress tests against historical drawdown periods (2008, 2020 COVID, 2022 rate shock). The price data and correlation infrastructure already support this.

High Impact Factor exposure reporting

After scoring, report the portfolio's aggregate factor exposures: how much value tilt, how much momentum, how much size. This is table-stakes for any institutional portfolio. The factor z-scores are already computed per name — aggregate them as position-weighted sums.

Medium Impact Drawdown control with dynamic position sizing

No automatic response to drawdowns. Add a trailing drawdown monitor that reduces position sizes proportionally when the portfolio drawdown exceeds a threshold (e.g., half-size at 10% drawdown, flat at 15%). The trade plan infrastructure already supports weight scaling.

4.2 Position-Level Risk

High Impact Trailing stops

quant/tradeplan.py — Stops are placed once and never adjusted. In trending markets this leaves significant profit on the table. Add: (1) ATR trailing stop that ratchets up as price advances, (2) chandelier exit (highest high minus N*ATR), (3) moving average trailing stop (close below 20-day EMA). Make the trailing method configurable per strategy.

Medium Impact Partial exits and scaling

Positions are all-or-nothing. Add: sell half at 1R profit and trail the remainder, or scale in (buy half at entry, add at first pullback to the MA). The PlanParams dataclass can be extended with scale_out_at_r and scale_out_pct fields.

Medium Impact Correlation-adjusted position sizing

Current sizing is per-position, ignoring correlations. Two 10% positions in highly correlated names are effectively a 20% bet. Adjust weights using the portfolio's pairwise correlation matrix: adjusted_weight = base_weight / sqrt(1 + avg_pairwise_corr).

5. Backtesting Engine

5.1 Methodology Improvements

High Impact Volume-dependent slippage model

Slippage is a flat 5 bps regardless of name size or liquidity. A $50M position in a $500M-ADV large-cap costs far less than a $50M position in a $5M-ADV small-cap. Implement a square-root market impact model: slippage = k * sqrt(trade_value / adv) where k is calibrated to historical fill data (typical values: 0.1-0.3).

High Impact Walk-forward optimization

No out-of-sample testing framework. Add walk-forward analysis: split history into rolling train/test windows, optimize factor weights on the train set (or select the best strategy), then test on the out-of-sample period. Report both in-sample and out-of-sample metrics to detect overfitting.

High Impact Monte Carlo simulation for confidence intervals

Backtest results are point estimates. Add bootstrap confidence intervals: resample return periods with replacement (block bootstrap to preserve autocorrelation), compute CAGR/Sharpe/maxDD for each sample, report 5th/50th/95th percentiles. This answers "how lucky/unlucky could the realized path have been?"

Medium Impact Benchmark selection

Hardcoded to SPY. A small-cap value strategy should be benchmarked against IWM or IWD, not SPY. Add configurable benchmark per strategy, with sensible defaults (e.g., momentum strategies vs. MTUM ETF, quality vs. QUAL).

Medium Impact Regime-conditional performance

Report performance split by market regime: bull/bear (defined by 200-day MA of SPY), high/low volatility (VIX above/below 20), rising/falling rates. This reveals whether a strategy's alpha comes from one regime or is persistent.

5.2 Research Diagnostics

High Impact Turnover-adjusted IC

quant/research.py — IC is reported raw. A factor with IC=0.05 and 100% monthly turnover is less valuable than IC=0.04 with 30% turnover. Report IC * (1 - turnover_rate) as a trading-cost-adjusted signal quality metric.

Medium Impact Per-factor IC attribution

When a composite score predicts returns, which factors drove the prediction? Decompose composite IC into per-factor contributions: for each factor, compute its marginal contribution to the composite's rank correlation with forward returns.

Medium Impact Rolling IC chart

IC decay reports the mean across periods but not the time series. Add a rolling IC chart showing how signal quality evolves: 6-month rolling IC with confidence bands. This catches factor decay (a signal that worked in 2018-2022 but died in 2023).

6. Data Pipeline & Database

6.1 Data Sources

Critical Backup price provider

Yahoo's undocumented chart API is the sole price source. If it breaks, there is no automatic failover. priceval.py can detect the problem but cannot fix it. Add a secondary price source (Polygon.io free tier, Alpha Vantage, or EODHD) with automatic failover when Yahoo returns errors or when cross-validation against Finnhub fails.

High Impact Dividend history table

Dividends are not stored anywhere in the data layer. Dividend yield comes from yfinance .info snapshots (which cannot be backfilled), not from actual dividend history. Add a dividends table sourced from Yahoo's chart API (which already returns dividend events in events.dividends). This enables accurate historical dividend yield computation and total-return backtesting.

High Impact Macro data pipeline

The macro table exists in the schema but has no data pipeline. Add FRED API integration for: 3-month T-bill rate (risk-free rate for Sharpe), 2Y/10Y spread (yield curve), VIX (from CBOE), credit spreads (BAA-AAA), ISM PMI, unemployment claims. These feed regime detection and benchmark-relative analytics.

Medium Impact Delisting and ticker change tracking

If a company is acquired or delisted, its ticker simply stops receiving updates but stale data remains forever. Add a ticker_events table tracking delistings, mergers, ticker changes, and spin-offs. Source from SEC submissions (form types SC 14D-9, 8-K item 2.01) and Wikipedia changes table (which already captures add/remove events).

6.2 Data Quality & Integrity

High Impact Foreign key constraints and CHECK constraints

No data integrity constraints beyond primary keys. Orphaned rows (e.g., sec_facts referencing a non-existent securities.ticker) are possible. Add CHECK constraints for value ranges (price > 0, market_cap > 0), and consider foreign keys for critical relationships. SQLite supports these with PRAGMA foreign_keys = ON.

Medium Impact Automated data quality scoring

The validate module runs 9 checks but produces no aggregate quality score. Add a data quality dashboard that computes: overall coverage score, staleness score, consistency score (cross-validation pass rate), and a composite quality grade. Track these over time to detect degradation before it affects results.

Medium Impact SEC submissions pagination

data/sec.py:235 — Only filings.recent is read from the submissions endpoint. SEC paginates older filings via filings.files[]. For companies with 1000+ filings, historical coverage is incomplete. Add pagination support for deeper filing history.

7. Factor Research

7.1 New Factor Families

High Impact Earnings quality factors

Beyond the existing ACCRUALS factor, add: (1) Sloan ratio (accruals / total assets, signed), (2) Cash conversion quality (OCF / net income consistency over 4 quarters), (3) Revenue quality (receivables growth vs. revenue growth — divergence signals channel stuffing), (4) Beneish M-Score (8-variable model for earnings manipulation). The SEC facts pipeline already provides all required inputs.

High Impact Short interest and options-derived signals

Add: (1) Short interest ratio (days to cover), (2) Short interest change (momentum of short interest), (3) Put/call ratio as a contrarian sentiment indicator. FINRA short interest data is freely available with a 2-week lag. Options data requires a provider (e.g., CBOE delayed data).

Medium Impact Cross-sectional dispersion factors

Add: (1) Analyst estimate dispersion (std dev of EPS estimates / mean), (2) Return dispersion (cross-sectional std dev of sector returns as a regime indicator), (3) Earnings surprise persistence (autocorrelation of SUE scores). These require analyst estimate data (consensus EPS), which could come from yfinance .info fields already partially captured.

7.2 Factor Pipeline Improvements

Medium Impact XBRL taxonomy coverage gaps

data/taxonomy.py — Missing mappings for: SGA (selling, general & administrative), depreciation/amortization (needed for EBITDA), income tax (effective tax rate), goodwill (acquisition-driven growth detection). Add these tags with appropriate fallback chains. Also add a taxonomy version monitor that alerts when FASB updates introduce new tags.

Medium Impact Factor decay monitoring

No automated detection of factor decay. A factor that produced IC=0.08 historically but IC=0.01 over the last 12 months is effectively dead. Add a factor health monitor that flags factors whose trailing 12-month IC falls below 50% of their full-sample IC, and suggests weight reduction.

8. Execution & Trade Management

High Impact Order generation with broker integration

The trade plan produces entry/stop/target levels but no executable orders. Add an order generation layer that outputs: (1) CSV/FIX-compatible order files for broker import, (2) Interactive Brokers TWS API integration for paper trading, (3) position reconciliation (compare suggested portfolio vs. actual holdings). Start with CSV export; broker API is a later phase.

Medium Impact Transaction cost analysis (TCA)

No post-trade analysis. After trades are executed, compare actual fills against the model's assumed entry prices. Track: implementation shortfall (model price vs. fill price), slippage by name size and time of day, and realized vs. expected R-multiples. This calibrates the slippage model for future backtests.

Medium Impact Rebalancing optimizer

Rebalancing is binary: the entire portfolio is rebuilt each period. Add a threshold-based rebalancer that only trades when a position's weight drifts more than N% from target, reducing turnover and transaction costs. Also add tax-loss harvesting awareness: prefer selling losers when multiple names need trimming.

9. NLP & Alternative Data

9.1 Sentiment & Extraction

Medium Impact Full Loughran-McDonald dictionary

nlp/sentiment.py — Uses a "representative subset" of ~180 negative and ~120 positive words, not the full LM dictionary (which has ~2,300 negative and ~350 positive). The full dictionary is freely available from Notre Dame. This would improve sentiment accuracy for SEC filings where LM was specifically designed to work.

Medium Impact Earnings call transcript analysis

No earnings call data. Add transcript ingestion from SEC EDGAR (many companies file transcripts as 8-K exhibits or FWP forms). Extract: management tone (positive/negative word ratio in Q&A vs. prepared remarks), uncertainty language frequency, forward-looking statement density. These are proven alpha signals in academic literature.

Medium Impact Wikipedia attention normalization

data/altdata.py — Raw pageviews are not normalized for overall Wikipedia traffic trends. A pageview in 2024 is not comparable to one in 2018. Add normalization against aggregate English Wikipedia traffic (available from the same Wikimedia API) to produce a relative attention score.

9.2 NLP Infrastructure

Medium Impact LLM response caching

LLM calls are not cached (except news synthesis). An identical screen explanation for the same data costs the same API call every time. Add content-addressed caching: hash the prompt + model + input data, store the response in a llm_cache table with a configurable TTL (e.g., 24 hours for screen explanations, 7 days for backtest interpretations).

Medium Impact Sentence splitting improvements

nlp/summarize.py — The regex (?<=[.!?])\s+(?=[A-Z"'(]) fails on abbreviations ("Inc. The", "U.S. Markets"). Replace with a proper sentence tokenizer (nltk's sent_tokenize is already a dependency) or add an abbreviation exception list.

10. Infrastructure & Testing

10.1 Test Coverage

The test suite has 160+ tests covering quant logic, data integrity, transforms, and providers. However, significant gaps exist:

  • Zero UI tests — no Dash testing infrastructure exists. Add Selenium or Playwright tests for critical paths (screen, backtest, builder).
  • No CLI tests — argparse and all cmd_* functions are untested. Add subprocess tests for each command.
  • No integration tests — the full ingest-score-backtest pipeline is never tested end-to-end. Add a smoke test with a tiny universe (3-5 tickers, 6 months) that runs the complete pipeline.
  • No Yahoo provider tests — the primary price source has zero test coverage. Mock the chart API response and test parsing, validation, and incremental fetch logic.
  • No Anthropic provider tests — only Gemini is tested in test_providers.py. Add mock tests for the Anthropic SDK path.
  • No policy module tests — Federal Register API parsing and sector mapping are untested.
  • No news module tests — RSS parsing, deduplication, and sentiment pipeline are untested.
  • No concurrency tests — ThreadPoolExecutor usage in intel.py and factors.py is never tested for race conditions.

10.2 Infrastructure Improvements

High Impact Database migration framework

Schema changes require manual DDL. Add Alembic (already using SQLAlchemy) for versioned migrations. This enables safe schema evolution as new tables and columns are added.

High Impact Dependency pinning with lock file

requirements.txt — No version upper bounds and no lock file. The anthropic SDK is commented out but used in code. Add a pyproject.toml with version constraints and generate a lock file. Pin the Anthropic SDK as a proper optional dependency.

Medium Impact Alerting and monitoring

No automated alerts. Add: (1) data freshness alert (email when essential sources are stale beyond 2x max_age), (2) data quality alert (when validate checks find new errors), (3) factor decay alert (when trailing IC drops below threshold), (4) portfolio risk alert (when concentration or drawdown exceed limits). The email infrastructure already exists in the reports module.

Medium Impact CLI improvements

Add: --dry-run for ingest (show what would be fetched), --json output format for all commands (enables scripting), progress bars via tqdm, and fix the --insider-days argument that is accepted but never passed through to the sync function.
